# 量化研发与八模块验证

> [!summary] 摘要
> 量化策略研发是一条从假说到受控上线的验证链，而不是“回测好看就上线”。八个模块分别回答不同问题；任何一环缺失，都会让后面的收益曲线失去解释力。

## 研发流程

假说 → 数据质量 → 无前视特征 → 策略形式化 → 订单状态测试 → 回测 → 归因 → 参数优化 → 稳健性 → 样本外 → 前向测试 → 受控上线。

每一步都应留下可复现的记录：数据版本、代码 commit、参数、成本假设、交易明细和失败原因。

## 核心原则

- 样本内最优 trial 不等于可部署的最优参数。
- 反复查看并筛选样本外结果，会污染最终验证。
- 一个策略的收益曲线不能直接推出多策略有效前沿。
- 回测、模拟盘和前向测试是不同证据层级，不能互相替代。

## 检查清单

- [ ] 假说是否有经济或行为机制，而不只是数据模式？
- [ ] 数据是否存在前视、幸存者偏差或合约拼接错误？
- [ ] 订单状态、部分成交和退出方式是否被正确建模？
- [ ] 是否完成参数、稳健性、尾部风险和样本外验证？
- [ ] 是否有明确的停机条件、版本变更和恢复流程？
