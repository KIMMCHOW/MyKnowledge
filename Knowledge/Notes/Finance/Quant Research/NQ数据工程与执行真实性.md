# NQ数据工程与执行真实性

> [!summary] 摘要
> NQ 数据工程的核心是统一合约、时区、交易日和连续合约口径，并让研究数据能够追溯到真实可交易合约。执行真实性则要求区分回测成交假设与实际订单事件。

## 合约与数据口径

- NQ tick size = $0.25$ 指数点，tick value = USD $5$。
- MNQ 对应 USD $0.50$/tick。
- 同时保存 UTC、ET 和 CME trading day。
- 夏令时使用 IANA 时区数据库，不写死偏移量。

## 数据流水线

原始字节 → Parquet tick → 分钟 OHLCV → 逐日/日内 POC → 连续合约映射。每一层都应有独立的数据审计：行数、时间范围、重复、缺失、异常价格和合约切换。

连续合约的调整价格主要用于研究信号；下单实际作用于特定到期合约。必须写明换月依据、前后合约映射和调整方法，避免制造虚假跳空。

## 执行真实性

NautilusTrader 等框架只提供执行容器，不能证明策略逻辑复现正确。Bar 级同根触价的先后顺序未必确定，touch ≠ fill；应检查订单状态、部分成交、撤单回报、滑点和断线恢复。

Globex Day Session 可以允许隔夜时钟时段，但不能跨 CME 交易日截止边界。Session 强平可视为合法退出设计，但必须与 target、stop、trailing 等退出分别归因。

## 检查清单

- [ ] tick size、tick value 和合约乘数是否与真实合约一致？
- [ ] UTC、ET、CME trading day 是否同时保存？
- [ ] 连续合约换月映射是否可追溯？
- [ ] 回测是否区分调整价格与实际合约价格？
- [ ] 订单状态、部分成交和断线恢复是否被测试？
- [ ] session 强平是否单独归因？
